#### b. Code Package Description

| **No** | **Package** | **Description** |
| --- | --- | --- |
| 1 | frontend/src/pages | React 18 + Vite SPA screens split by role (`public`, `student`, `teacher`, `admin`, `shared`). Routing in `App.jsx` is guarded by `ProtectedRoute` / `TeacherRoute` / `AdminRoute` (based on `user_metadata.role`) and wrapped in role layouts. Includes billing pages (`Pricing`, `SubscriptionStatus`, `BillingHistory`, `AdminPayments`…). |
| 2 | frontend/src/components | Reusable React components: `ui` design-system primitives (`Button`, `Modal`, `DataTable`, `FuriganaText`…) and feature widgets (`dictionary`, `flashcards`, `mockexam`, `receipt`…), plus `layout` and `shared` route-guard wrappers. |
| 3 | frontend/src/contexts | App-wide Context providers: `AuthContext` (Supabase auth state + role), `LangContext` (vi/ja i18n), `ConfirmContext` and `PageContext`. |
| 4 | frontend/src/lib | Front-end services/helpers: `api.js` (shared axios instance; interceptor attaches the Supabase Bearer JWT and normalises errors), `supabase.js` (PKCE auth client), `useProctoring` + `faceDetector` (camera/gaze exam monitoring), and formatting/parsing utilities. |
| 5 | routes/ + views/ (EJS server) | Legacy Express 5 + EJS server-rendered site with Postgres session auth (`connect-pg-simple`); `routes/*.js` map to `controllers/*.js` and render EJS views. Scope: public landing page and Supabase OAuth callback. |
| 6 | backend/routes/api | Thin Express 4 route layer (`backend/app.js` mounts ~24 groups under `/api/*`). Each router only wires middleware (`requireAuth` / `requireAdmin` / `requireTeacher` / `optionalAuth`, `checkQuota`) to controller methods — no business logic. |
| 7 | backend/controllers | Domain request handlers (one file per area), pattern `exports.action = async (req,res)=>{ try…catch }`. Read/write Postgres via `supabaseAdmin` (service-role, bypasses RLS), apply pagination, return `{data}`/`{error}`. Includes payment controllers (`subscriptionController`, `coursePaymentController`, `revenuePoolController`, `webhookController`). |
| 8 | backend/services | Reusable business logic called by controllers: `courseAccess` / `subscriptionService` / `quotaService` (paid access + limits), `paymentOrderService` / `paymentMatchingService` / `revenuePoolService` (payments + revenue split), `examGuard` / `passThreshold` (exam grading), `aiTools/*`, and Japanese text/audio processing (`jaTokenizer`, `furiganaService`). |
| 9 | Payment gateway (SePay) | SePay integration via `services/sepayClient.js` (SePay UserAPI, Bearer token) and webhook `POST /api/webhooks/sepay` (`webhookController`). On a transfer, the order is matched by amount + content (`paymentMatchingService`), access is granted (`courseAccess` / `subscriptionService`), revenue recorded, and a receipt emailed. Backs the `payment_orders` / `subscriptions` tables. |
| 10 | backend/config | External-service clients: `supabase.js` (`supabase` anon + `supabaseAdmin` service-role), `ai.js` (FPT AI Factory Chat Completions — chat, question gen, grading, furigana), `mailer.js` (Nodemailer SMTP — OTP, receipts), plus `audio.js`/`youtube.js` and SePay credentials. |
| 11 | backend/middleware | Cross-cutting Express middleware: `auth.js` (`requireAuth` validates the Supabase JWT and sets `req.user`; `requireAdmin` / `requireTeacher` role checks; `optionalAuth`), `checkQuota.js` (per-plan limits), `metrics.js` (traffic + response-time metrics). |
| 12 | database/ | PostgreSQL schema for Supabase: idempotent `schema.sql` + incremental `migrate.sql` / `backend/migrations/NNN_*.sql`. Organised into feature schemas (accounts, learning content, quizzes, JLPT/mock-exam bank, billing…) with a public compatibility layer of views and `INSTEAD OF` triggers, plus the `handle_new_user` provisioning trigger. |
